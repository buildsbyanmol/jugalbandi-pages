Planned architecture from the product specification. The contracts and budgets below are design requirements, not shipped capabilities or measured benchmarks.

Capture, persistence & crash recovery Foundations / Phase 0

Official hooks redact observations before writing a local spool. Capture does not require a running daemon. One daemon ingests the spool, redacts again, and writes the canonical log.

  1. ObserveSupported hook payload
  2. Redact & spoolLocal durable capture
  3. IngestSingle daemon writer
  4. ProjectJSONL → SQLite
Source of truth
Append-only JSONL, per project and stream, under ~/.jugalbandi/log/. Logs stay outside pushed repositories.
Provenance
Keep the redacted vendor payload, normalized event, and normalizer version. A gapless sequence and hash chain make record continuity inspectable.
Recovery contract
Repair a torn log tail on startup. Ingest spooled events without loss or duplicate records. Rebuild the SQLite index from the log.
Redaction failure
Drop the raw payload when redaction fails. Query results and data/ contents stay out of the log, bridge, and packet; retain tool, path, size, and hash instead.
Handoff construction & delivery CLI handoff / Phase 1a

A pure builder and two-phase cursor combine recorded events, project/git state, and the receiving session's cursor. Context belongs to the project; no prime agent owns all memory.

New session
Use records since the last accepted close, or a seven-day fallback window.
Resumed session
Send only the delta since its cursor. Move the cursor only after a stop confirms the agent ran; a crash before confirmation resends the delta.
Packet contract
15 fixed sections, dead ends before changes, at most 9,000 characters including standing orders and gate warnings. Every item carries a source reference retrievable with handoff_get.
Delivery
Choose a supported delivery path proved by a capability probe on the installed harness version. If session-start delivery is missed, the first prompt carries the packet once.
Trust boundary
Sanitize, redact, label authors, and mark packet text as data. A refused task cannot be handed to another harness.
Interfaces, permissions & failure modes Local daemon / CLI handoff
Typed operations
One Zod operation registry drives the CLI, socket operations, and MCP tools. The stateless stdio MCP shim forwards agent operations to the daemon.
Separate doors
Two Unix sockets: agent/hook and human. Socket permissions 0600 inside a 0700 directory. No TCP listener. Human-only operations never appear as MCP tools.
Initial MCP surface
handoff_get retrieves referenced context. dead_end records a failed approach. A review-only profile adds submit_review. General collaboration tools arrive in Phase 2.
Native permissions
Official Claude Code and Codex retain execution, sandboxes, and permission prompts. Jugalbandi never types into a pane or answers those prompts.
Gates without daemon
Native controls, local hooks, and git guards evaluate locally. On gate error, deny calls matching a Tier 1 fallback pattern; pass other calls and log the error. Coverage depends on the mechanism.
Adapter drift
Pin and probe harness versions. A changed Codex app-server schema drops the adapter to pull-only. No vendor login token is reused.
Quota & failures
Detect quota from supported harness interfaces and show source/freshness. Missing information stays “no quota data.” Only quota or tool errors may suggest a different harness, with human confirmation. Safety refusals, configuration blocks, and unclear failures lock the task against rerouting.
Coordination, ownership & human decisions Collaboration / Phase 2

The structured bridge connects addressed messages, exact replies to claims, reviews, tasks, leases, and versioned contracts. It records who said what and who owns the next action. Discussion uses bridge primitives rather than a rigid debate mode.

Task ownership
One lease holder with a fence. Laptop sleep does not expire ownership. Reclaim only after confirming the holder is dead and no action is in flight.
File ownership
Exclusive path-prefix leases. A git guard blocks an agent commit touching another holder's path using a sufficiently fresh local snapshot.
Contract changes
Compute the version bump. A breaking stable contract waits for affected subscribers' compatibility acknowledgements with evidence, or a human decision.
Human acceptance
Show options and evidence, then preview the exact decision record. Acceptance records the decision and returns it to the parties. Silence is never approval.
Cross-vendor review
Earlier Phase 1a review is read-only, pinned to a commit and diff hash, limited to one review depth, and cannot mark work verified.
Workspace, terminals & observability Desktop / Phase 1b

The workspace is a Tauri shell with a Node sidecar and a separate PTY host behind a SessionHost interface. Terminal sessions are designed to survive daemon and app restarts.

Agent observability
See sessions, assigned tasks, who is waiting, and questions that need your decision.
Code observability
Follow structured file, tool, check, and review events beside terminal output. Select an event to jump to the related terminal position.
Recorded sessions
Search retained scrollback and scrub finished sessions. This is terminal playback, not hidden reasoning or a separate agent memory.
Data boundary
Structured events are redacted before disk. Raw terminal recordings are a separate local, display-only store with limited retention: seven days, or 24 hours for projects marked as containing personal data. They do not feed the log, bridge, or handoff packet.
Project documents
The daemon is the sole project-file writer. Drafted state and decisions are written only after your acceptance; project documents remain the authority for your accepted decisions.
Memory, vector search & MCP access Recall / Phase 3 · optional mem0 backend

Agents can search project memory through the read-only MCP recall tool. One RecallBackend interface supports SQLite FTS5 and optional self-hosted mem0 for vector-backed semantic retrieval.

Default & fallback
SQLite FTS5 stays current even when mem0 is selected. The source log remains authoritative; vector memory does not replace it.
Vector layer
mem0 manages memory retrieval over its configured vector store. The referenced self-hosted design uses PostgreSQL with pgvector. This is accessed through Jugalbandi's recall interface, rather than unrestricted database access for agents.
Local setup
Optional mem0 must run on loopback with an approved local embedding provider. Hosted mem0 and external embedding providers are outside this design. Enable only after configuration and health checks pass.
Write semantics
Store verbatim with infer=false, retaining provenance and source references. Decisions are immutable. Recall documents never outlive their source records.
Operations
Planned CLI controls: jb memory status, jb memory use fts5|mem0, jb memory doctor, and jb memory reindex.
Release scope
The MCP recall and optional vector-memory integration are Phase 3 work. The initial handoff release uses the event log, packet builder, handoff_get, and dead_end.
