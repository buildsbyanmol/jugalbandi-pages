The notes behind the महफ़िल.

A short guide to what Jugalbandi is being built to do.

Planned product · No public release available

The tools do the work.

Jugalbandi is a local control plane for official Claude Code and Codex harnesses. It records supported events, prepares relevant handoffs, connects work, and brings decisions to you. Each harness retains execution, safety, tools, permissions, and its sandbox.

How context continues

  1. Hooks redact supported observations before writing a local spool record.
  2. One on-demand daemon ingests records and writes the append-only JSONL log.
  3. SQLite indexes that record. The index can be rebuilt from the log.
  4. The handoff builder combines a recorded window, project/git state, and a session cursor.
  5. A supported integration delivers the relevant context to the receiving harness.

Every recorded item keeps its source. Jugalbandi does not read another tool's private memory or hidden reasoning. Later search and recall are separate roadmap work.

What comes first

  1. Foundations. Local capture, redaction, log, gates, and a handoff baseline.
  2. CLI handoff. Context packets, failed approaches, jb close, status, and scoped cross-vendor review.
  3. Workspace. A planned Tauri app with terminals, structured event rails, attention, and quota visibility. It follows the handoff validation gate.
  4. Collaboration. Typed messages, exact replies, ownership leases, reviews, and contracts.
  5. Recall. Local search and additional handoff surfaces.

Your decision stays yours.

Human-only actions use a separate local interface. Decisions preview their exact record before acceptance. The bridge cannot answer native harness permission prompts. Rules use available native controls and local hooks; their strength depends on the mechanism.

The small stack

Node.js 24, TypeScript, and Zod. Local append-only JSONL with a rebuildable SQLite index. Agents connect through a stateless stdio MCP shim. The planned desktop shell uses Tauri. Local product communication uses Unix sockets, with no TCP listener.

Memory and vector retrieval · Phase 3

A read-only MCP recall tool exposes one recall interface to agents. SQLite FTS5 is the default and remains the fallback. Optional self-hosted mem0 provides vector-backed retrieval using local embeddings and its configured vector store; the referenced design uses PostgreSQL with pgvector. Agents use the scoped recall interface rather than direct database access.

mem0 requires loopback hosting and an approved local embedder. Verbatim writes (infer=false) retain provenance; decisions stay immutable, and recall documents follow source retention. If mem0 is unhealthy, FTS5 responds with degraded-backend status. This integration is planned Phase 3 work, separate from initial CLI handoff.

Release and setup

There is no verified public package or installation command to recommend yet. The planned first target is macOS. Beta interest registration is connected through Google Forms. Choose a desktop preference and leave an email for beta access and launch updates. The landing page's interactions use sample records and quota figures.
